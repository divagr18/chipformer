# RV32 inside Qwen3.5: P0 feasibility

`chipformer/rv/` compiles a RISC-V RV32I core into stock Qwen3.5 Gated DeltaNet + SwiGLU layers
with the same q35 compiler as the CHIP-8 machine (`chipformer/q35/ir.py`, `prims.py`,
`emit.py`). Everything below is measured on this branch (`rv-p0`) unless marked *estimate*.

## Design as built

### Trace format (`spec.py`)
One record per instruction; state changes only at a record's last token, and the PC is implied:
PC = ROM_BASE + 4·(anchor + n), with the anchor the payload of the latest J/R token and n the commits
since (an R refresh is emitted before the instruction when n reaches 63).

| Record | Tokens |
|---|---|
| rd-writing (ALU, LUI, AUIPC, loads) | `F0` · `V F1` · `V V F2` by the value's sign-extended size (15-bit chunks) |
| rd = x0, not-taken branch, FENCE | `NT` |
| taken branch, JAL, JALR | `J(word)`; the link rd = PC+4 is computed in-circuit |
| SW | `ST0`/`ST1` (the RAM value head = address bit 6); the data is rs2 from t-1, in-circuit |
| SB, SH | `V V V SS0/SS1`: the merged word (old bytes merged at the top of the circuit) |
| ECALL, EBREAK, illegal | `HALT` |

Vocabulary: V, F0, F1, J, R × 32,768 + F2 × 4 + 7 controls = **163,851 rows**.

### The commit rule
Every position computes the instruction its *next* token belongs to: at a record's last token
the circuit already works on the next instruction; inside a record it recomputes the current one.
A write takes its **key from t-1** (a conv tap), its **write gate beta from the token at t** (beta =
sigmoid(256 g − 128) with g ∈ {≤0, 1}, exactly 0 or 1), and its **value from token payloads at lags
0..3 or from dims computed at t-1 below the writing layer**. The payload-to-bit wiring needs no
constants (which would break at the sequence start): for "V bit at t-1 when t is F1" the channel is
P = −Vb + isF1 + isV with taps (1, −1), which equals the bit exactly when t is F1 and is ≤ 0
otherwise. Information only flows down through tokens, so nothing writes a value computed above
its own layer at the same position; that is why the PC is implied rather than written.

### Memory
| Table | Layout | Read | Write |
|---|---|---|---|
| ROM (code) | 16 key heads × 2 value heads; row pairs (p, p+64); 8 bytes per instruction **pre-decoded** at load: (uop, rdw, rs1, rs2) in value head 0, imm in value head 1; byte-valued columns | 2-hot query {p, p+64} (effective q scale 2^-4, exact for bytes); the word is selected by z per column block, so no select MLP | snapshot only |
| registers | 2 key heads (rs1, rs2 ports), 32 rows, 109 columns per row (payload sources per bit + the link) | one-hot query; a bit = sum of its columns | key rdw(t-1), beta = F0+F1+F2+J |
| RAM | 16 key heads × 2 value heads × 128 rows × 1 word = 16 KB per sublayer; key head = EA[5:2], value head = EA[6], row = EA[13:7] | one-hot query, z picks the value head | key = address(t-1) AND store(t-1); beta = ST_x/SS_x |
| pc, count, prev | 1 head each | | J/R payload; 2^-n decay counter; token kinds at lags 1-3 |

The ROM is a compiled image, so static facts are folded in (`ref.rom_fields`): rdw = rd only if
the instruction writes rd, AUIPC/LUI are constants, branch and JAL targets are absolute words.
The uop byte has room for the custom-0/custom-1 bignum ops planned for P2.

Address map: **RAM at 0** (.data from 0x100, the stack below 0x4000), **ROM at 0x10000**. RAM at
the bottom makes data and stack pointers 1-token values: 1.42 → 1.19 tokens per instruction on
the small-C mix.

### Datapath (8 layers)
| Layer | Attention | MLP (units) |
|---|---|---|
| L1 | pc, count, prev (3 heads) | n thermometer, record position j (129) |
| L2 | — | PC word w = anchor + n, link w+1, thresholds + carry into bit 6 (1,072) |
| L3 | ROM (16) | field one-hots, immediate bits, gated link (4,660) |
| L4 | registers (2) | adder stage 1 for 4 operand modes (generate / propagate / digit bits per nibble), logic ops, shifter stage 1, store data (5,216) |
| L5 | — | adder stage 2 (carries and result bits in one stage), shifter stage 2 (1,008) |
| L6 | RAM (16) | load lanes / sign extension, SB/SH merge, SLT/SLTU/zero (492) |
| L7 | — | rd value select, its size class, branch decision (190) |
| L8 | — | output code: family id + 15-bit payload (175) |

The 32-bit add is 2 MLP sublayers: nibble sums are free linear forms, then stage 1 thresholds them
per operand mode (with the mode as an AND literal, so no operand mux layer), then stage 2 applies
the carry sources as AND literals on the digit bits.

## Measurements (`python -m chipformer.rv.measure --nonzeros`)
- **Size:** 884 IR dims, 37 heads, 12,942 MLP units; **298,676 nonzero weights** in the 8 chip layers.
  At 4B width the dense chip layers hold 1.08B parameters, almost all zeros. The ROM, RAM and
  registers live in the recurrent state, not in the weights.
- **Capacity per sublayer:** ROM 64 KB (pre-decoded, 8 bytes per instruction), RAM 16 KB (words).
- **Tokens per instruction:**
  - Measured on gcc -O2 C programs (crc32, sieve, sort, strops): **1.40**. Byte stores are 4 tokens
    and sieve is store-heavy.
  - The small-C mix from P0.6 gives **1.19**, against 3-5 for CHIP-8.
- **Payload width:**

| Chunk bits | Value records (1/2/3 tokens) | Tokens per instruction, mix | Vocabulary rows | Embedding at 3072 wide |
|---|---|---|---|---|
| 12 | 20.4k / 4.2k / 2.6k | 1.44 (2-token jumps) | 20.7k | 0.13 GB |
| **15** (built) | 23.6k / 2.2k / 1.4k | **1.19** | 164k | 1.01 GB |
| 16 | 23.7k / 3.5k / — | 1.11 (SB/SH as V+SS) | 459k | 2.82 GB |

  Recommendation: keep 15-bit V/F and make **J/R 16-bit** (+65k rows), since 256 KB ROMs need
  16-bit word indices (MicroPython with float is 229 KB).
- **HF cache snapshot (R11):** injecting the initial states into `DynamicCache` recurrent states
  after a zero (text-token) prefix works for prefill and decode (`hf.py`). Static cache not tried.
- **Speed (*estimates*; GPU pending):**
  - The dense HF path reads 1.08B chip parameters per token at 4B width.
  - The existing compact path (`fast.compact`) was measured at 1.3 ms for a 16-layer chip step on
    an L40S (speed fork). Scaled to 8 layers that is about 0.65 ms, so roughly 1.5k tok/s or 1.3k
    instr/s.
  - A fused executor over the 0.3M nonzeros with one-hot gather/scatter rows is launch-bound:
    10-20k tok/s *estimate*.

## Options measured or costed
- **8-byte granule RAM rows** (the spike fork's alternative): 2× RAM per sublayer, but SW becomes
  4 tokens (+0.27 tokens per instruction on the mix). RAM needs are tiny (P0.6: at most 16 KB
  touched), so word rows stay.
- **ROM density:** pre-decoded 64 KB per sublayer. 256 KB = 4 sublayers, which adds about 3 layers
  of fetch depth. The alternative is raw 4-byte words at 128 KB per sublayer plus one decode
  MLP stage. Pick for P1 against the depth budget.
- **SB/SH cost** is 4 tokens with 15-bit payloads; 2 with 16-bit (V + SS16).

## P1 / P2 extrapolation (*estimates*)
- **P1** (all RV32I, MUL via 5 parallel MLP stages, putchar/exit, 128 KB ROM, 32-64 KB RAM): MUL
  runs beside the adder/RAM path (L4-L8), so it adds no depth. The ROM grows to 2 sublayers (+1),
  RAM to 2-4 sublayers (+1..3) and output select (+1), giving **11-13 layers**.
- **P2** (256 KB ROM, micro-coded DIV, CARRY/instret, custom bignum ops): **16-20 layers**.

## Gaps
- **GPU numerics (P0.2)** on the fla `chunk` and `fused_recurrent` kernels, bf16 and fp32:
  `python -m chipformer.rv.gpucheck --decode`.
- **Timing (P0.5):** `python -m chipformer.rv.timing --hidden 3072`.
- **Count-head snapshots with n > 0** need a decayed-row level in the IR's initial-state check
  (snapshots start at n = 0 today).
- **Not in the P0 circuit:** MUL*, DIV*/REM*, putchar, faults (misaligned, out of range), text I/O.
- `fence_i` (self-modifying code) and `ma_data` (misaligned access) are skipped, as planned.
